# Casevo 实验设计快速开始

本文用于从零设计新实验，不沿用旧实验的情境和参数。所有路径均相对于 `competition/`；下面的新实验目录和文件是建议结构，尚未创建。

## 1．先写清实验，再写代码

为新实验取一个目录名，例如 `experiment_01`，先编写 `论文/experiments/experiment_01/design.md`，填写以下内容：

| 必须确定 | 填写提示 |
| --- | --- |
| 研究问题 | 改变什么，观察谁的什么行为或状态？用一句话描述。 |
| 假设 | 预期哪个指标如何变化？什么结果会不支持该假设？ |
| 个体与环境 | Agent 代表谁？每人有哪些属性？环境和网络如何定义？ |
| 实验条件 | 首轮只改变一个主要因素；设置合适的无干预或基准条件。 |
| 控制变量 | 哪些角色、初始状态、网络、模型、提示词和轮数应保持一致？ |
| 时间线 | 初始化何时完成？何时干预？一轮包含哪些动作？同步还是顺序更新？ |
| 可见信息 | 每人能看到哪些事件、邻居发言和记忆？研究者知道的真值如何隔离？ |
| 主要指标 | 明确计算公式、记录时间和方向，区分收到信息、接受信息与实际行动。 |
| 重复方案 | 每条件重复多少次？如何配对种子、角色位置与初态？ |
| 资源与失败 | 调用量如何估算？超时、无效输出和预算耗尽时如何处理？ |

**完成标准：** 不看代码，也能解释各条件之间唯一计划改变的因素，以及如何判断结果。

## 2．确认本地环境与凭据位置

在 `competition/` 根目录执行：

```bash
conda activate alien
python --version
python -c "import casevo; print(casevo.__file__)"
python -m pip check
```

目前已确认：Python 3.12.15、Casevo 0.3.19、Mesa 2.4.0、ChromaDB 1.5.9，Casevo 可导入。

- 框架源码：`论文/casevo-main/src/casevo/`。
- 实际导入位置：`alien` 环境的 `site-packages`，以命令输出为准。编辑本地框架源码不会自动改变已安装包。
- 保留的凭据文件：`论文/experiments/clarification/.env`。该目录目前只有凭据，旧实验实现和结果已删除。

新实验可以显式读取现有凭据文件，不必复制密钥。读取时只使用需要的变量；模型与地址可以在新实验中重新选择。

| 环境变量 | 用途 |
| --- | --- |
| `CASEVO_CHAT_BASE_URL`、`CASEVO_CHAT_MODEL`、`CASEVO_CHAT_API_KEY` | 文本生成服务 |
| `CASEVO_EMBEDDING_BASE_URL`、`CASEVO_EMBEDDING_MODEL`、`CASEVO_EMBEDDING_API_KEY` | 向量服务，启用语义记忆时使用 |
| `CASEVO_MAX_TOTAL_TOKENS` | 可沿用为预算配置变量，但新程序必须自行实现其含义 |

`.env` 不会由 Casevo 自动读取；旧适配器也已删除。后续需在新入口或适配器中实现加载。密钥不写入提示词、日志或配置快照；确保凭据文件继续被 Git 忽略。

## 3．按最小职责建立文件结构

建议每项独立实验使用一个新目录：

```text
论文/experiments/
├── Casevo实验设计快速开始.md
├── clarification/
│   └── .env                     # 已保留的实际凭据
└── experiment_01/              # 以下均为待创建
    ├── design.md               # 问题、条件、时间线、指标与失败规则
    ├── config.json             # 可调整参数，不含密钥
    ├── inputs.json             # 角色、初态、事件或实验材料
    ├── prompts/
    │   ├── act.txt             # 判断与行为输出要求
    │   └── reflect.txt         # 反思模板
    ├── llm_adapter.py          # 模型接入、模拟模式、重试与调用统计
    ├── agent.py                # 个体状态与行为
    ├── model.py                # 网络、全局事件、调度与消息投递
    ├── run.py                  # 加载输入、创建模型、运行与保存
    ├── analyze.py              # 根据日志计算指标和生成结果
    ├── .gitignore              # 忽略凭据、缓存及运行产物
    ├── runs/<运行编号>/         # 每次运行独立保存，避免覆盖
    │   ├── manifest.json       # 配置、版本、条件、种子和完成状态
    │   ├── states.jsonl        # 各节点每轮状态
    │   ├── events.jsonl        # 事件及实际消息投递
    │   ├── calls.jsonl         # 实际请求、用量、失败和重试
    │   ├── memory_trace.jsonl  # 记忆写入、检索与注入记录
    │   ├── prompts/           # 实际提交的提示词
    │   ├── responses/         # 原始模型响应
    │   └── memory/            # 本次运行的独立向量库
    └── results/<运行编号>/      # 指标表、图和结果说明
```

`config.json` 至少规划：节点及边、条件、轮数、种子、模型标识、采样与输出参数、记忆检索数量、重试和预算。复杂输入增加后，再把 `inputs.json` 拆成角色、网络和材料文件。

路径在代码中以 `Path(__file__).resolve().parent` 为基准解析，显式传入提示词、记忆和输出位置，避免启动目录变化导致文件找不到。

## 4．将实验规则对应到 Casevo 组件

| 实现位置 | 接入方式与职责 |
| --- | --- |
| `论文/experiments/experiment_01/llm_adapter.py` | 实现 `LLM_INTERFACE` 的 `send_message`、`send_embedding`、`get_lang_embedding`；向量函数需符合已安装 Chroma 的接口要求。提供固定输出的模拟模式。 |
| `论文/experiments/experiment_01/agent.py` | 继承 `AgentBase`，保存人设、当前状态、行为和记忆；定义自己的 `step` 或由同步模型统一调用行为函数。 |
| `论文/experiments/experiment_01/model.py` | 继承 `ModelBase`，建立网络，通过 `add_agent` 加入个体，定义全局事件和每轮执行顺序。 |
| `论文/experiments/experiment_01/prompts/` | 定义可见上下文和输出格式；判断可使用 `JsonStep`，仍需额外校验字段、类型及范围。 |
| `论文/experiments/experiment_01/run.py` | 读取配置与凭据，初始化模型，执行轮次，保存版本快照和失败状态。 |
| `论文/experiments/experiment_01/analyze.py` | 只读取已保存数据计算结果，避免重新调用模型改变原始结果。 |

当前 `ModelBase` 初始化会创建记忆工厂，并默认加载 `reflect.txt`。使用时显式指定 `prompt_path` 和 `memory_path`，保证反思模板存在。若设计不使用记忆，需要另行处理初始化方式，不能仅靠省略文件来关闭它。

## 5．先固定“一轮”的执行顺序

如果选择同步更新，建议按以下顺序实现：

1. 固定上一轮状态、已分享消息与本轮外部事件。
2. 沿合法网络边建立每个 Agent 的收件箱，记录真实投递。
3. 写入实际经历，检索本人可见记忆，组装全部 Agent 的判断输入。
4. 生成并校验所有新判断与行为，暂不让其他节点读取。
5. 统一提交新状态；已分享消息留到下一轮投递。
6. 如启用反思，更新本人长期记忆供下一轮使用，然后保存日志。

必须补充的规则：

- **同步调度：** 默认 `ModelBase.step()` 使用随机激活。需要同步传播时，在实验层实现输入快照和输出缓冲；串行调用 LLM 也可以保持同步。
- **记忆注入：** 创建记忆对象不代表提示词已经使用记忆。需主动检索并加入相关短期记忆与旧长期记忆，记录实际输入。
- **条件隔离：** 每个条件、每次重复分别建立 Agent、消息队列和向量库。持久化向量库本身不等于完整断点恢复。
- **输出与失败：** 固定 JSON 字段及范围；不把异常输出填成默认分数。确定重试总上限，避免适配器与思维链重试叠加。
- **干预比较：** 若研究干预，明确干预前基线、干预后初态和后续轮次；网络位置的度数、角色等差异要记录为可能混杂因素。

## 6．按顺序启动，不直接跑大规模实验

| 阶段 | 操作 | 通过标准 |
| --- | --- | --- |
| 模拟检查 | 少量 Agent，固定模型输出，先跑一轮 | 状态可保存，投递合法，未分享不投递，输入时序正确。 |
| 接口检查 | 单独测试文本、结构化输出；需要记忆时测试向量写入与查询 | 模型名、请求格式、返回内容和向量维度均正确。 |
| 小规模试跑 | 一个条件、少量 Agent、少量轮次 | 全部结束；记忆确实进入后续提示；失败与用量可追溯。 |
| 正式对照 | 冻结配置、提示词与判定规则，再运行各条件及重复 | 条件之间可配对；失败运行和探索试跑单独保存。 |
| 分析 | 输出主要指标、节点状态及可追溯事件记录 | 从图表能回查实际输入与事件；区分观测结果与解释。 |

模型 API 的地址、模型 ID、思考参数与 JSON 能力，在真实接入时核对服务商官方文档。Token 预算中的 `0` 是否表示无上限，必须由新代码明确实现；单次输出长度、请求次数和运行时长分别配置。

**当前没有实验启动命令**：旧实现已删除。新 `run.py` 完成后，把真实可执行命令写入该实验的 `design.md`。

## 7．可直接使用的设计与实现提示

把下面内容填写后交给开发助手；不确定的项先标为“待确定”：

```text
请基于本地 Casevo 设计一个新的最小实验。

实验目录：论文/experiments/[实验名]/
研究问题：[一句话]
Agent 与环境：[代表谁、个体数、角色属性、网络]
实验条件：[基准条件与改变的因素]
初始状态与事件：[各条件相同或不同的内容]
执行方式：[同步/顺序、轮数、每轮动作]
可见信息与记忆：[谁能看到什么、如何检索与反思]
主要指标：[计算方法、记录时间、预期方向]
重复与预算：[角色映射、种子、次数、调用上限]

先完善 design.md，再建立最小文件结构并实现模拟运行。
复用 Casevo 的 Agent、Model 和记忆组件，明确实验层需要补充的逻辑。
凭据显式读取论文/experiments/clarification/.env，不输出密钥。
记录真实提示词、状态、消息投递、记忆检索和请求用量。
本阶段只实现与验证模拟流程，不发起真实 API 请求。
```

开始编码前，优先完成第一节的设计表；后续每加一个机制，都写清它改变了哪个变量、需要记录什么、怎样验证。
